## Scope and actors

Problem/outcome: doc 01 — segment-2 SME leader gets an explained, trustworthy on-target verdict without hiring anyone. Release/phase: doc 02 MVP row.
In scope: manual/CSV-uploaded pipeline and P&L data (itemized or monthly-total, never both for the same period — RULE-015); orders and their monthly outstanding allocations plus explicit unscheduled outstanding value (owner-maintained, no mandatory invoice reconciliation); a detailed monthly budget by customer/sector/product-service/salesperson (budget_lines/budget_line_months, REQ-017), authoritative over the simpler annual-target fallback once it exists (RULE-017); deterministic calc engine for month/quarter/year target-vs-actual using invoiced + outstanding order book against budget (pipeline explicitly excluded from this figure); per-dataset freshness tracking with mismatch flagging (RULE-016); explained "why" reasoning; stale-deal detection; a two-segment (invoiced/order-book) annual trajectory; a short onboarding step capturing four explicit Commercial Baseline benchmarks (sales-cycle length, revenue target, margin target + minimum acceptable margin, stale-opportunity threshold), editable afterward via a Company Settings page; single pilot user per business, basic login, no billing.
Out of scope: live Xero OAuth (doc 02 — V1); multi-tenant roles/permissions beyond per-business data isolation; billing/payments; segment 3 (win-driver attribution, capacity matching — doc 02 V2); marketing/procurement modules; public self-serve signup; onboarding fields with no corresponding calc rule yet — business type/B2B-B2C, seasonality, new-vs-existing mix, win-rate expectation, average deal value (V1); subjective data-confidence self-report — the objective confidence bands in RULE-009 already cover this more reliably; quote-validity/"at risk" as a signal distinct from stale-deal detection (V1 — a second staleness signal stacked onto an untested first one). **Resolved, 2026-09-19 — customer/product/salesperson budget breakdown IS MVP, per REQ-017.** Automatic invoice-to-order reconciliation is not built at MVP, but is not permanently rejected either — see RULE-013's corrected wording.

| RULE-001 | **Commercial benchmarks** (sales-cycle days, revenue target, margin target + minimum acceptable margin, stale-opportunity-threshold days) are captured explicitly during onboarding (REQ-013) and are never silently overwritten by observed data — a benchmark stays exactly what the business set until the business changes it. ## Worked example: order lifecycle (reference for AC-016-01–04)

Order: Acme Ltd, £150,000 total value (context only — never a calculation input for outstanding). Allocations set by the owner: Feb £50,000, Mar £50,000, Apr £50,000. Unscheduled outstanding: £0.

- **Mid-month partial invoicing (the case the first draft of this example missed entirely):** during March, £20,000 is invoiced against this order (appears in `pnl_lines`). The owner updates March's allocation from £50,000 to **£30,000** — not to zero, since only part of it has actually been invoiced. March's trajectory contribution from this order = £20,000 (invoiced) + £30,000 (still-outstanding allocation) = **£50,000** — matching the original plan, not £70,000. The allocation reflects what's genuinely still outstanding, not what's left after subtracting something that hasn't happened yet.
- **Rescheduling overdue work:** April arrives and £15,000 of March's allocation still hasn't invoiced. The owner moves it: March's allocation → £0 (nothing further expected there), April's allocation increases by £15,000 to reflect the deferred amount. No value is created or destroyed — it's relocated to the month it's now actually expected.
- **Completing below original value:** by the time the order is finished, only £142,000 was ultimately invoiced against a planned £150,000 (a commercial adjustment — reduced scope, tolerance, whatever the reason). The owner marks the order **complete**. Every remaining allocation and the unscheduled-outstanding field are set to £0 immediately, regardless of the £8,000 variance from the original total. No reconciliation between £142,000 and £150,000 is required or attempted.
- **Explicitly unscheduled outstanding work:** a separate order, £40,000 total, has £25,000 allocated to specific months and £15,000 the owner hasn't yet scheduled to any month. That £15,000 sits in `unscheduled_outstanding_value` — visible as its own state, counted in the order's current outstanding total, but never attributed to any specific period's trajectory and never computed by subtracting allocations from total value.
